# Evaluation limits — 2026-09-14

The 3,000-message corpus repeats four templates across 1,000 synthetic multilingual event groups. Its perfect current need metrics measure template regression only. A Turkish water suffix was added after seeing a miss on this corpus, so this is also a development set, not held-out validation.

The separate 18-message challenge set contains six authored examples per language: negation, implicit water/shelter/food requests, explicit rescue/medical needs and an ended exercise. Current micro precision is 0.60, recall 0.50 and F1 0.545 in each language. Need exact match is 2/6. These matching results follow parallel authored examples, not statistically equivalent language performance. Greek text and all labels need independent native-speaker/domain review.

This small challenge exposes concrete failures: keyword presence overcalls negated injuries/trapped people, while indirect descriptions of thirst, homelessness and hunger are missed. The baseline keeps every report visible and requires human review; these controls do not establish operational safety. Do not use scores to suppress reports or authorize dispatch.

`baseline-results.json` and `challenge-results.json` are reproducible via `scripts/evaluate.py`. Inference latency is local in-process rule execution, excluding HTTP, database, queues, geocoding and human review. Unmeasured location, duplication and time-to-triage fields remain null.

`translation-diagnostic.json` compares raw OPUS output and the guarded postcondition on the same six authored cases over four direct directions and both EN-pivot directions. Raw output retained every numeral in 3/6 cases, target-language negation in 1/4 and selected names verbatim in 0/6. The guarded candidate made those observable markers present in 6/6, 4/4 and 6/6 by visibly appending missing values inside `⟦…⟧` and recording recovery warnings. This does not prove that a recovered value is grammatically attached to the correct clause, that an address was interpreted correctly, or that the rest of the meaning survived. Transliteration also makes verbatim name checking pessimistic. Neither result is BLEU/COMET or human adequacy. The candidate is not promoted. `translation-pipeline-smoke.json` proves route/model provenance and warnings survive the actual pipeline; the PII-free CSV/JSON package under `translation-review-package` is ready for bilingual offline review, but no completed human review has been imported.

The classification quality stage adds a disclosed split and error analysis in `classification-candidate-results.json`. On the new 36-row same-author synthetic holdout, deployed `rules-0.1` produced need precision 0.5714, recall 0.2667, F1 0.3636 and urgency accuracy 0.3889, including six missed critical-urgency rows. The guarded rules candidate produced 1.0 for these measures and zero listed failures, which is a strong regression result but suspiciously favorable because the rules and authored set share an author. The local scikit-learn character TF-IDF/logistic experiment produced precision 0.50, recall 0.3333, F1 0.40, urgency accuracy 0.3889 and five missed critical rows. Its training corpus has only four repeated positive templates and no food examples. The predeclared synthetic thresholds therefore do not override the independent-evidence gate: runtime stays on `rules-0.1`, all outputs remain review-only, and no classifier can suppress, merge or dispatch.

The updated `duplicate-retrieval-diagnostic.json` separates 60 development and 60 held-out synthetic event groups and scores semantic, location, time, address and needs evidence without injecting the gold building label. Threshold 0.85 produced precision/recall/F1 1.0 and zero false candidates in every language on the test split. The result is intentionally not promoted: repeated same-author templates, exact coordinates and explicit `Synthetic training building N` addresses expose the grouping. It proves the scorer blocks the known different-building fixtures, not field duplicate accuracy. Runtime output remains a reasoned human comparison candidate and cannot merge cases.

Next validation needs independently labelled, consented/de-identified multilingual incident data, incident-level train/test separation, Turkish/Greek native-speaker review, confidence calibration and an actual end-to-end load benchmark. The existing challenge is development data; the new authored holdout must also be replaced or externally reviewed before any default promotion.

`whisper-diagnostic.json` reports two clean Windows TTS fixtures, one TR and one EN, with micro WER 0.3793. Synthetic TTS is much easier and less varied than telephone/field audio; it is a plumbing smoke test. No Greek clip, real voice, noise/accent matrix, hallucination measurement or automatic language-detection evaluation exists. The adapter remains disconnected from ingestion.
