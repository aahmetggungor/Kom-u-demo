# Short voice report capture

Android asks for `RECORD_AUDIO` only when the user starts a recording. Denial leaves text reporting available and displays an explicit message. The user sees elapsed seconds and can stop, cancel, record again or remove the draft. Capture uses `VOICE_RECOGNITION`, one channel, signed 16-bit PCM at 16 kHz and stops at 30 seconds. Recordings below 0.2 seconds, above the bound or below the same conservative RMS/peak speech gate as the server are rejected.

On save, the generated canonical WAV is written to app-private storage and its metadata is inserted with the report in Room v3. The audio row is keyed by the local report UUID and tenant; no arbitrary file path is stored. WorkManager first obtains the durable server report receipt, then uploads that exact WAV to the report audio endpoint. A crash before the local receipt causes a safe identical replay (`200`); temporary network/5xx/408/429 responses remain queued. `401`/`403`, `409`, validation failure and missing/changed private files remain visible fixed states. Re-authentication only resumes the active tenant. The local file is deleted after a committed successful audio receipt; server retention owns the accepted encrypted copy.

The development web form offers a WAV picker and browser microphone capture. Browser samples are bounded, downsampled to the same canonical 16 kHz mono PCM format, checked for size/duration/energy and uploaded only after the report is accepted. If the audio request fails, submitting again reuses the same report UUID and identical audio. Permission denial, unsupported browser recording and invalid files are shown explicitly in Turkish, Greek and English. Microphone data is not logged or sent to analytics.

Evidence on 2026-09-15: web production build and 11 tests; Android debug APK, lint, six app unit tests, seven relay tests and six Room instrumentation tests on a Pixel 7 / Android 14 emulator. The emulator tests cover v2→v3 migration and audio custody across database reopen. A live local API smoke returned `202` for the report, `201` for its first audio upload and `200` with `replayed=true` for the identical retry. A physical microphone, browser/device compatibility matrix, airplane-mode recording/upload and real field audio remain unverified.
